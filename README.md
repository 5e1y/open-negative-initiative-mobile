# ONI Mobile

The iPhone remote for Open Negative Initiative (ONI), the film-negative editor.
The desktop shows the photo full screen; the phone holds the Scanner face's keypad:

- **The scanner screen**: frame, machine and channel, the D C M Y TEMP counts, then Contrast, Vignette and Chrome,
  written exactly as the desktop writes them.
- **The keypad**: per letter −3, −1, the letter (back to zero), +1, +3, in the desktop's band colours;
  Contrast, Vignette and Chrome (no Chrome in black and white); ONI or Frontier; previous and next frame;
  undo and redo. A press shows on the phone at once and the desktop's screen settles it.
- **Import**: pick photos in the library and send them to the desktop as their original files. A ProRAW scan
  of a negative on a light table arrives as its DNG, never as a JPEG rendition.

The phone talks to the desktop over the local network: ONI Link (Noise IK, paired once by a QR code) for the
keys, LocalSend v2 for the photos. The Rust side is the `oni-link-ffi` crate of
[open-negative-initiative-rs](https://github.com/5e1y/open-negative-initiative-rs),
exported to Swift with UniFFI.

## Build on a Mac

You need Xcode 15 or later, [rustup](https://rustup.rs), [XcodeGen](https://github.com/yonaskolb/XcodeGen)
(`brew install xcodegen`), and `open-negative-initiative-rs` checked out next to this repository
(or `ONI_RS=/path/to/open-negative-initiative-rs`).

```sh
scripts/build-rust.sh          # adds the iOS Rust targets, builds Frameworks/OniLinkFFI.xcframework,
                               # regenerates ONIMobile/Generated/oni_link_ffi.swift
DEVELOPMENT_TEAM=ABCDE12345 xcodegen generate
open ONIMobile.xcodeproj
```

The XCFramework holds `aarch64-apple-ios` (iPhone) and `aarch64-apple-ios-sim` (the simulator on Apple silicon).
Run `scripts/build-rust.sh` again after any change to `oni-link` or `oni-link-ffi`, then build in Xcode.

### Without Xcode's licence

On a Mac where Xcode's licence has not been accepted, so `xcodebuild` and XcodeGen refuse to run,
`scripts/run-simulator.sh` builds the Rust library and the app straight from the toolchain and runs it on an
"ONI Mobile Test" simulator. Installing on a real iPhone still needs Xcode with its licence accepted.

To run on a device: plug the iPhone in, choose it as the run destination, and run. The first launch asks for
the camera (to read the pairing code), the local network (to reach the desktop) and, on the first import,
the photo library (to read original files).

## Pair

1. On the desktop, show ONI's pairing code. It stays valid for two minutes and pairs one phone.
2. On the phone, hold the camera up to the code. Without a camera, copy the `oni-link://pair?…` link,
   paste it, and press PAIR.

The phone keeps its key and the desktop's in the Keychain, on this device only, and reconnects by itself on
launch and on every return to the app. **Forget Desktop** (the ⋯ menu) drops them; the desktop keeps trusting
the phone until it is revoked there.

Phone and desktop must be on the same network. The phone dials the addresses the code carried: if the desktop's
address changes, pair again.

## Layout

```
project.yml               the Xcode project, generated by XcodeGen
scripts/build-rust.sh     the Rust library and the bindings
scripts/run-simulator.sh  the app on a simulator, without xcodebuild
ONIMobile/
  ONIMobileApp.swift      the app: pairing or remote, reconnects on foreground
  Link/                   the session model, the Keychain, the screen's number formats
  UI/                     pairing (camera, paste), the remote, the keypad, the screen, import
  DesignSystem/           the desktop's Keycap, ported to UIKit, and the tokens it needs
  Generated/              UniFFI's Swift bindings, header and modulemap
  Resources/Keycap/       the keys' click
```
